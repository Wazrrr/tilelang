# A100 experiment review — 2026-09-17

The active suite contains two FP16 GEMMs, two attention cases, two KDA
chunk-output cases and two native FP8 GEMMs. Softmax was removed from the
experiment registry, manifest, runners and family directory. Its general
TileLang example and model regression tests remain available.

Status: revised baseline collection is running. Measured comparisons and
heuristic exports will be added after collection and winner validation finish.
Earlier results under this root describe different source versions and are
not substituted for the revised study.

## Changes

- FP8 GEMM directly calls the native example: FP8 A/B/C, transposed B and FP32
  accumulation. Final shapes are 4096³ and 8192³, E4M3FN; E5M2 is also supported.
  Each pool has 2,304 configs, including all 288 example configurations.
- Carver reuses MatmulTemplate for both GEMM families. FlashAttentionTemplate
  now includes scaling, stable normalization, causal masking and the probability
  cast. KDAChunkOutputTemplate includes gating, both query rounding points,
  query/state multiplication and causal A/V. Both graph adapters retain
  Carver's traffic-times-waves priority and record their scheduling assumptions.
- KDA's example no longer overwrites the pipeline input Q_shared. Explicit
  casts preserve both rounding points and allow positive pipeline stages.
- CUDA properties load from PyTorch's versioned runtime. Carver uses opt-in
  per-block shared memory and actual per-SM capacity.
- TileTune resolves native compiler layouts for attention reductions and
  broadcasts. Register estimates include inferred ownership and last-use
  narrowing copies with equal thread ownership, without strengthening rejection
  proofs. Analysis version 25 models FP8 output conversion separately; profile
  version 7 measures E4M3FN/E5M2 conversion at aggregate SM and single-CTA rates.
  Missing or incompatible profiles leave scores unknown.
- Baseline runtime discovery avoids oversized subprocess arguments. Unsupported
  cases remain explicit. Heuristic export validates full immutable oracles and
  remeasures winners seven times while retaining measurement identity.
- XGBoost fingerprints the kernel and execution dependencies separately from
  study/export orchestration. The former broad fingerprint rejected the 8192³
  prediction after unsupported-case orchestration changed. A new baseline
  identity retrains XGBoost from the independent saved training/validation
  measurements and remeasures both final GEMM selections. GEMM oracle and Carver
  artifacts are copied byte-for-byte only after proving that their complete
  measurement identity is unchanged; `measurement-reuse.json` records hashes
  and original paths. The failed original bundle remains intact.

## Hardware and protocol

One NVIDIA A100 80GB PCIe is available: 108 SMs, PyTorch 2.7.0+cu126,
CUDA compiler 12.4, driver 575.57.08, g++ 10.5 and Python 3.10. A100 cannot
execute native FP8 GEMM. Both FP8 cases remain in the matrix as unsupported;
there are no FP8 timing claims or replacement FP16 measurements. Both formats
and their conversion probes cross-compile for Hopper; GPU validation still
requires suitable hardware.

The six supported cases retain 6,688 oracle candidates: 2 × 2,304 GEMM,
2 × 320 attention and 2 × 720 KDA. All failures retain their original slots.
Baselines use seed 123. XGBoost trains on a seeded 10% of independent training
and validation pools, without final-oracle labels.

Timing uses CUDA events, streaming inputs, a 256 MiB cache flush outside the
measurement, warmup=10 ms and rep=50 ms timing budgets, and eight compilation
workers. The profiler derives iteration counts from a preliminary timing.
TileTune uses
K=20, seeds 123/456/789 and seven winner remeasurements. Primitive profiles
contain no candidate-grid fitting or workload latency anchor. The GPU monitor
polls every second; accepted measurements must be observed uncontended.
Polling cannot exclude shorter interference.

Artifacts: [results/a100-review-20260917](results/a100-review-20260917).
Fresh bundles use baselines-revised. Historical/interrupted runs are preserved.

## Reproduction

Run from the repository root with CUDA_HOME=/root/cuda-12.4,
CXX=/usr/bin/g++-10, CUDA_VISIBLE_DEVICES=0 and OMP_NUM_THREADS,
MKL_NUM_THREADS and OPENBLAS_NUM_THREADS all set to 1.

```bash
python -m experiments.suite --suite full --devices ampere --workers 8 \
  --warmup 10 --rep 50 --timeout 60 --case-timeout 7200 \
  --baseline-root experiments/results/a100-review-20260917/baselines-revised \
  --output experiments/results/a100-review-20260917/tiletune-revised

python -m experiments.common.brute_force --device ampere \
  --baseline-study experiments/results/a100-review-20260917/tiletune-revised \
  --output experiments/results/a100-review-20260917/heuristics-revised
```

Use bash experiments/compare_results.sh on each saved ranking and its complete
oracle. Oracle@K is oracle-best latency divided by the fastest correct oracle
latency among the first K candidates. Failures consume K. This is kernel
performance retention, not tuning-time speedup. Exact configuration dictionaries
and measurement identities are checked before joining results.

## Verification

- CPU experiments, TileTune and template checks: 597 passed, 75 skipped,
  three deselected; final-cpu-tests.log. The later standalone unsupported FP8
  regression and four heuristic-export tests also passed.
- Final KDA FP16/BF16 reference checks covered regular and tail dimensions and
  positive pipeline stages. With FP8 Carver tagging checks, the focused GPU
  run passed 11 tests. Representative KDA models score at all stages 0–4.
- Both final FP8 shapes score with matching synthetic profiles; missing
  conversion rates and FP16 profiles leave them unscored. These checks validate
  model behavior only, not prediction accuracy.
- E4M3FN/E5M2 examples and conversion probes cross-compile for sm_90a. CUDA 12.4
  cannot compile the existing sm_100a probe test.
- Native build required no rebuild. Ruff and diff checks pass.

Offline compiler audit: four unscored noncausal-attention schedules reported
200–956 bytes of spill stores and 168–684 bytes of spill loads in PTXAS output.
Two scored schedules reported no spills. These six checks are saved in
`attention-register-audit.json`; they explain examples of the model's coverage
boundary without asserting that every unscored schedule has the same cause.

Compiler scratch registers, memory-system effects and occupancy remain model
estimates. Unsupported layouts and spills remain visible. A score is not a
claim of cycle-accurate execution. Full eight-case acceptance cannot pass on
A100 while native FP8 measurements are unavailable.
